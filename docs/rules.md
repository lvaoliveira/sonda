## common/cognitive-complexity

**Cognitive complexity of functions should not be too high.** Deeply nested and heavily branched functions are hard to understand and change. Cognitive complexity adds 1 per branch, loop, catch or boolean-operator sequence, plus the current nesting depth for nested structures. Threshold: `thresholds.cognitive_complexity`.

SonarQube: S3776

## common/function-length

**Functions should not be too long.** Long functions usually do too many things. Threshold: `thresholds.function_lines`.

SonarQube: S138

## common/too-many-parameters

**Functions should not have too many parameters.** Many parameters make calls hard to read; group them into an object. Threshold: `thresholds.parameters`.

SonarQube: S107

## common/todo-comment

**Track TODO and FIXME comments.** TODO, FIXME and XXX comments mark unfinished work that should be tracked.

SonarQube: S1134, S1135

## js/no-eval

**eval() should not be used.** eval() executes arbitrary strings as code and is a common injection vector.

SonarQube: S1523 (related)

Noncompliant:

```javascript
eval(userInput);
```

Compliant:

```javascript
JSON.parse(userInput);
```

## js/no-new-function

**The Function constructor should not be used.** new Function(...) compiles strings into code, just like eval().

SonarQube: S1523 (related)

Noncompliant:

```javascript
const f = new Function('a', 'return a');
```

Compliant:

```javascript
const f = (a) => a;
```

## js/inner-html

**HTML should not be assigned through innerHTML/outerHTML.** Assigning strings to innerHTML or outerHTML can lead to cross-site scripting.

Noncompliant:

```javascript
el.innerHTML = html;
```

Compliant:

```javascript
el.textContent = text;
```

## js/eqeqeq

**Strict equality operators should be used.** `==` and `!=` perform type coercion with surprising results. Comparisons against `null`/`undefined` are allowed.

SonarQube: S1440

Noncompliant:

```javascript
if (a == b) { f(); }
```

Compliant:

```javascript
if (a === b) { f(); }
if (x == null) { g(); }
```

## js/assignment-in-condition

**Assignments should not be used as conditions.** `if (x = y)` is almost always a typo for `===`. Wrap in extra parentheses if intended.

SonarQube: S1121 (related)

Noncompliant:

```javascript
if (x = 5) { f(); }
```

Compliant:

```javascript
if (x === 5) { f(); }
if ((m = re.exec(s))) { g(); }
```

**debugger statements should not be committed.** debugger statements pause execution in any open devtools.

SonarQube: S1525

Noncompliant:

```javascript
function f() { debugger; }
```

Compliant:

```javascript
function f() { return 1; }
```

## js/no-var

**let or const should be used instead of var.** var is function-scoped and hoisted, which causes subtle bugs.

SonarQube: S3504

Noncompliant:

```javascript
var x = 1;
```

Compliant:

```javascript
let x = 1;
const y = 2;
```

## js/empty-catch

**Exceptions should not be silently swallowed.** An empty catch block hides failures. Handle the error or explain with a comment.

SonarQube: S2486 (related)

Noncompliant:

```javascript
try { f(); } catch (e) {}
```

Compliant:

```javascript
try { f(); } catch (e) { /* best effort */ }
```

## js/no-console

**console calls should not be left in production code.** Use a proper logger instead of console.* calls.

Noncompliant:

```javascript
console.log('hi');
```

Compliant:

```javascript
logger.info('hi');
```

## js/jump-in-finally

**finally blocks should not return, throw, break or continue.** A jump out of a finally block discards whatever the try or catch block was doing: its return value or its exception is silently lost.

SonarQube: S1143

Noncompliant:

```javascript
function f() { try { return g(); } finally { return 0; } }
```

Compliant:

```javascript
function f() { try { return g(); } finally { for (;;) { break; } cleanup(); } }
```

## js/no-with

**with statements should not be used.** Inside `with`, a bare name may refer to a property of the object or to a variable, depending on the object at run time. Strict mode forbids it.

SonarQube: S1321

Noncompliant:

```javascript
with (config) { f(port); }
```

Compliant:

```javascript
const c = config; f(c.port);
```

## js/duplicate-parameter

**Parameter names should be unique.** When two parameters share a name, the later one hides the earlier, whose argument becomes unreachable.

SonarQube: S1536

Noncompliant:

```javascript
function move(x, y, x) { return x + y; }
```

Compliant:

```javascript
function move(x, y, z) { return x + y + z; }
```

## js/self-assignment

**Variables should not be assigned to themselves.** `x = x` has no effect. It usually means another variable or property was meant.

SonarQube: S1656

Noncompliant:

```javascript
this.name = this.name;
```

Compliant:

```javascript
this.name = name;
items[i++] = items[i++];
```

## js/identical-operands

**Both sides of an operator should not be identical.** `a === a`, `a - a` or `a && a` always give the same result, so one side is almost always a copy-paste mistake. `x !== x` (a NaN test) and `h & h` (a 32-bit integer conversion) are idioms and allowed.

SonarQube: S1764

Noncompliant:

```javascript
if (a.length === a.length) { f(); }
```

Compliant:

```javascript
if (a.length === b.length) { f(); }
const r = next() - next();
const m = 1 << 1;
```

## js/duplicate-condition

**Conditions in an if/else-if chain or switch should be unique.** A condition repeated further down an if/else-if chain, or a repeated switch case, can never be reached: the first one always wins.

SonarQube: S1862

Noncompliant:

```javascript
if (x === 1) { a(); } else if (x === 2) { b(); } else if (x === 1) { c(); }
```

Compliant:

```javascript
if (x === 1) { a(); } else if (x === 2) { b(); }
switch (y) { case 1: a(); break; case 2: b(); }
```

## js/nan-comparison

**NaN should not be compared with operators.** NaN is not equal to anything, itself included, so `x === NaN` is always false.

SonarQube: S2688

Noncompliant:

```javascript
if (value === NaN) { reset(); }
```

Compliant:

```javascript
if (Number.isNaN(value)) { reset(); }
```

## js/reversed-compound-assignment

**'=+', '=-' and '=!' should not be used.** `x =+ 1` assigns `+1` to `x`; it was almost certainly meant as `x += 1`.

SonarQube: S2757

Noncompliant:

```javascript
total =+ price;
```

Compliant:

```javascript
total += price;
sign = -1;
let ready = !busy;
```

## js/delete-variable

**delete should only be used on object properties.** `delete` removes properties. On a variable it does nothing (and is a syntax error in strict mode).

SonarQube: S3001

Noncompliant:

```javascript
delete cache;
```

Compliant:

```javascript
delete cache[key];
cache = undefined;
```

## js/case-with-comma-or-or

**switch cases should not combine values with ',' or '||'.** `case 1, 2:` matches only 2, and `case a || b:` matches only the value of `a || b`. Neither matches any of the listed values.

SonarQube: S3616

Noncompliant:

```javascript
switch (day) { case 'sat', 'sun': rest(); }
```

Compliant:

```javascript
switch (day) { case 'sat':
case 'sun': rest(); }
```

## js/empty-destructuring

**Destructuring patterns should not be empty.** `const {} = obj` binds nothing. A default value was usually meant: `const { a = {} } = obj`.

SonarQube: S3799

Noncompliant:

```javascript
const { options: {} } = settings;
```

Compliant:

```javascript
const { options = {} } = settings;
const [, second] = pair;
```

## js/negated-in-instanceof

**Negated 'in' and 'instanceof' operands should be parenthesized.** `!key in obj` negates `key` first and then tests `false in obj`; `!a instanceof B` is always false.

SonarQube: S3812

Noncompliant:

```javascript
if (!err instanceof TypeError) { retry(); }
```

Compliant:

```javascript
if (!(err instanceof TypeError)) { retry(); }
```

## js/negated-equality-operand

**A negated operand should not be compared for equality.** `!a === b` compares the boolean `!a` with `b`, not `a` with `b`.

SonarQube: S7736

Noncompliant:

```javascript
if (!status === 'ok') { warn(); }
```

Compliant:

```javascript
if (status !== 'ok') { warn(); }
const same = !a === !b;
if (!0 === x || !!y === z) {}
```

## js/new-symbol-bigint

**Symbol and BigInt should not be called with new.** Symbol() and BigInt() are functions, not constructors: `new` throws a TypeError.

SonarQube: S3834

Noncompliant:

```javascript
const id = new Symbol('id');
```

Compliant:

```javascript
const id = Symbol('id');
```

## js/invalid-typeof

**typeof should be compared with a type it can return.** typeof only returns "undefined", "object", "boolean", "number", "bigint", "string", "symbol" or "function"; a comparison with anything else is always false.

SonarQube: S4125

Noncompliant:

```javascript
if (typeof x === 'array') { f(); }
```

Compliant:

```javascript
if (typeof x === 'object') { f(); }
if ('string' === typeof y) { g(); }
```

## js/setter-return

**Setters should not return a value.** The value returned by a setter is discarded: `o.x = v` always evaluates to `v`.

SonarQube: S2432

Noncompliant:

```javascript
class A { set x(v) { this._x = v; return this; } }
```

Compliant:

```javascript
class A { set x(v) { if (v == null) { return; } this._x = v; this.on(() => { return 1; }); } }
```

## js/generator-without-yield

**Generators should yield.** A generator that never yields produces an empty sequence; it was probably meant to be a plain function, or a yield is missing.

SonarQube: S3531

Noncompliant:

```javascript
function* ids() { return [1, 2, 3]; }
```

Compliant:

```javascript
function* ids() { yield* [1, 2, 3]; }
function* none() {}
```

## js/duplicate-member

**Object literals and classes should not define a member twice.** When a key or member name repeats, the last definition silently replaces the earlier ones.

SonarQube: S1534

Noncompliant:

```javascript
const o = { port: 80, host: 'a', 'port': 8080 };
```

Compliant:

```javascript
const o = { port: 80, host: 'a', get v() { return 1; }, set v(x) {} };
class A { static of() {} of() {} }
```

## js/useless-increment

**A variable should not be assigned its own post-increment.** `i = i++` stores the old value back into `i`, so the increment is lost.

SonarQube: S2123

Noncompliant:

```javascript
count = count++;
```

Compliant:

```javascript
count++;
prev = count++;
```

## js/for-wrong-direction

**A for loop should move its counter toward the end condition.** `for (i = 0; i < n; i--)` moves away from its bound, so the loop never ends or ends only on overflow.

SonarQube: S2251

Noncompliant:

```javascript
for (let i = 0; i < n; i--) { f(i); }
```

Compliant:

```javascript
for (let i = 0; i < n; i++) { f(i); }
for (let i = n; i > 0; i -= 2) { f(i); }
```

## js/identical-branches

**Every branch of a conditional should not do the same thing.** When all branches of an if/else chain or a ternary are identical, the condition is pointless, or one branch was meant to differ.

SonarQube: S3923

Noncompliant:

```javascript
if (fast) { run(); } else { run(); }
```

Compliant:

```javascript
if (fast) { run(); } else { walk(); }
if (a) { run(); } else if (b) { run(); }
```

## js/error-not-thrown

**Errors should be thrown, not just created.** `new Error(...)` on its own line creates an error and drops it. `throw` was almost certainly forgotten.

SonarQube: S3984

Noncompliant:

```javascript
if (!ok) { new TypeError('bad input'); }
```

Compliant:

```javascript
if (!ok) { throw new TypeError('bad input'); }
```

**Literals should not be called as functions.** Calling a string, number or other literal always throws a TypeError. It usually comes from a missing semicolon before a parenthesized line.

SonarQube: S6958

Noncompliant:

```javascript
const s = 'a'
(items || []).forEach(f);
```

```javascript
const s = 'a';
(items || []).forEach(f);
const q = sql`select 1`;
```

## js/exclusive-test

**Exclusive tests should not be committed.** `it.only` and `describe.only` silently skip every other test in the run, so CI stays green while tests are ignored.

SonarQube: S6426

Noncompliant:

```javascript
it.only('adds', () => { add(1, 2); });
```

Compliant:

```javascript
it('adds', () => { add(1, 2); });
test.skip('later', () => {});
```

## js/shadowed-builtin-name

**undefined, NaN, Infinity, eval and arguments should not be redefined.** Binding or assigning these names makes code that relies on their standard meaning misbehave. Strict mode rejects most such uses.

SonarQube: S2137

Noncompliant:

```javascript
function f(arguments) { let undefined = 1; return arguments; }
```

Compliant:

```javascript
function f(...args) { const n = arguments.length; return undefined === n || isNaN(n); }
```

## js/tls-unverified

**TLS certificate checks should not be turned off.** `rejectUnauthorized: false` accepts any certificate, so anyone on the network path can impersonate the server.

SonarQube: S4830

Noncompliant:

```javascript
https.request({ host, rejectUnauthorized: false });
```

Compliant:

```javascript
https.request({ host, ca: fs.readFileSync('ca.pem') });
```

## js/weak-hash

**Weak hashing algorithms should not be used.** MD2, MD4, MD5, SHA-1 and RIPEMD-160 are broken for security purposes.

Noncompliant:

```javascript
crypto.createHash('md5').update(password);
```

```javascript
crypto.createHash('sha256').update(data);
```

## js/number-precision-loss

**Number literals should not lose precision.** Numbers are 64-bit floats: a literal with more precision than that, like 9007199254740993, silently becomes a different number.

SonarQube: S6534

Noncompliant:

```javascript
const id = 9007199254740993;
```

Compliant:

```javascript
const id = 9007199254740993n;
const max = 9007199254740991;
const x = 0.1 + 1e21 + 0xFF;
```

```typescript
let x: any = 1;
```

## py/no-eval

**eval() and exec() should not be used.** eval()/exec() run arbitrary code and are a common injection vector.

Noncompliant:

```python
eval(user_input)
```

Compliant:

```python
ast.literal_eval(user_input)
```

## py/subprocess-shell

**Commands should not be run through a shell.** shell=True passes the command through /bin/sh, enabling command injection.

Noncompliant:

```python
subprocess.run(cmd, shell=True)
```

Compliant:

```python
subprocess.run(['ls', '-l'])
```

**Untrusted data should not be unpickled.** pickle.load()/loads() can execute arbitrary code embedded in the data.

Noncompliant:

```python
data = pickle.loads(blob)
```

Compliant:

```python
data = json.loads(blob)
```

## py/mutable-default

**Default arguments should not be mutable.** Default values are evaluated once, so a list/dict/set default is shared between calls.

SonarQube: S5717 (related)

Noncompliant:

```python
def f(items=[]):
    return items
```

Compliant:

```python
def f(items=None):
    return items or []
```

## py/assert-tuple

**assert should not be called on a tuple.** `assert (cond, msg)` asserts a non-empty tuple, which is always true.

SonarQube: S5905

Noncompliant:

```python
assert (x > 0, 'x must be positive')
```

Compliant:

```python
assert x > 0, 'x must be positive'
```

## py/bare-except

**Bare except clauses should not be used.** `except:` also catches SystemExit and KeyboardInterrupt. Catch a specific exception.

SonarQube: S5754 (related)

Noncompliant:

```python
try:
    f()
except:
    pass
```

Compliant:

```python
try:
    f()
except ValueError:
    pass
```

## py/none-comparison

**None should be compared with 'is'.** `== None` can be overridden by __eq__; use `is None` / `is not None`.

Noncompliant:

```python
if x == None:
    pass
```

Compliant:

```python
if x is None:
    pass
```

## java/string-reference-equality

```java
class A { boolean f(String s) { return s == "x"; } }
```

Compliant:

```java
class A { boolean f(String s) { return "x".equals(s); } }
```

```java
class A { void f() throws Exception { MessageDigest.getInstance("MD5"); } }

```


## java/print-stack-trace

**printStackTrace() should not be used.** Stack traces printed to stderr bypass logging and may leak internals.

Noncompliant:

```java
class A { void f(Exception e) { e.printStackTrace(); } }
```

Compliant:

```java
class A { void f(Exception e) { log.error("failed", e); } }
```

## java/system-exit

**System.exit() should not be called.** System.exit() shuts down the whole JVM, which is rarely what library or server code wants.

SonarQube: S1147

Noncompliant:

```java
class A { void f() { System.exit(1); } }
```

Compliant:

```java
class A { void f() { throw new IllegalStateException(); } }
```

## java/system-out

**System.out and System.err should not be used for logging.** Use a logger so output can be filtered, formatted and routed.

SonarQube: S106

Noncompliant:

```java
class A { void f() { System.out.println("x"); } }
```

Compliant:

```java
class A { void f() { log.info("x"); } }
```

## c/no-gets

**gets() should never be used.** gets() cannot limit input size and always allows a buffer overflow.

Noncompliant:

```c
void f(char *b) { gets(b); }
```

Compliant:

```c
void f(char *b, int n) { fgets(b, n, stdin); }
```

## c/unsafe-string-function

**Unbounded string functions should not be used.** strcpy, strcat, sprintf and vsprintf do not check the destination size.

Noncompliant:

```c
void f(char *d, const char *s) { strcpy(d, s); }
```

Compliant:

```c
void f(char *d, const char *s, int n) { snprintf(d, n, "%s", s); }
```

## c/assignment-in-condition

**Assignments should not be used as conditions.** `if (x = y)` is almost always a typo for `==`. Use double parentheses if intended.

Noncompliant:

```c
void f(int x) { if (x = 5) { g(); } }
```

Compliant:

```c
void f(int x) { if (x == 5) { g(); } if ((x = h())) { g(); } }
```

## c/goto

**goto should not be used.** goto makes control flow hard to follow.

Noncompliant:

```c
void f(void) { goto end; end: return; }
```

Compliant:

```c
void f(void) { return; }
```
