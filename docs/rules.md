## common/cognitive-complexity

**Cognitive complexity of functions should not be too high.** Deeply nested and heavily branched functions are hard to understand and change. Cognitive complexity adds 1 per branch, loop, catch or boolean-operator sequence, plus the current nesting depth for nested structures. Threshold: `thresholds.cognitive_complexity`.

SonarQube: S3776

## common/function-length

**Functions should not be too long.** Long functions usually do too many things. Threshold: `thresholds.function_lines`.

SonarQube: S138

## common/too-many-parameters

**Functions should not have too many parameters.** Many parameters make calls hard to read; group them into an object. Threshold: `thresholds.parameters`.

SonarQube: S107

## common/todo-comment

**Track TODO and FIXME comments.** TODO, FIXME and XXX comments mark unfinished work that should be tracked.

SonarQube: S1134, S1135

## js/no-eval

**eval() should not be used.** eval() executes arbitrary strings as code and is a common injection vector.

SonarQube: S1523 (related)

Noncompliant:

```javascript
eval(userInput);
```

Compliant:

```javascript
JSON.parse(userInput);
```

## js/no-new-function

**The Function constructor should not be used.** new Function(...) compiles strings into code, just like eval().

SonarQube: S1523 (related)

Noncompliant:

```javascript
const f = new Function('a', 'return a');
```

Compliant:

```javascript
const f = (a) => a;
```

## js/inner-html

**HTML should not be assigned through innerHTML/outerHTML.** Assigning strings to innerHTML or outerHTML can lead to cross-site scripting.

Noncompliant:

```javascript
el.innerHTML = html;
```

Compliant:

```javascript
el.textContent = text;
```

## js/eqeqeq

**Strict equality operators should be used.** `==` and `!=` perform type coercion with surprising results. Comparisons against `null`/`undefined` are allowed.

SonarQube: S1440

Noncompliant:

```javascript
if (a == b) { f(); }
```

Compliant:

```javascript
if (a === b) { f(); }
if (x == null) { g(); }
```

## js/assignment-in-condition

**Assignments should not be used as conditions.** `if (x = y)` is almost always a typo for `===`. Wrap in extra parentheses if intended.

SonarQube: S1121 (related)

Noncompliant:

```javascript
if (x = 5) { f(); }
```

Compliant:

```javascript
if (x === 5) { f(); }
if ((m = re.exec(s))) { g(); }
```

## js/no-debugger

**debugger statements should not be committed.** debugger statements pause execution in any open devtools.

SonarQube: S1525

Noncompliant:

```javascript
function f() { debugger; }
```

Compliant:

```javascript
function f() { return 1; }
```

## js/no-var

**let or const should be used instead of var.** var is function-scoped and hoisted, which causes subtle bugs.

SonarQube: S3504

Noncompliant:

```javascript
var x = 1;
```

Compliant:

```javascript
let x = 1;
const y = 2;
```

## js/empty-catch

**Exceptions should not be silently swallowed.** An empty catch block hides failures. Handle the error or explain with a comment.

SonarQube: S2486 (related)

Noncompliant:

```javascript
try { f(); } catch (e) {}
```

Compliant:

```javascript
try { f(); } catch (e) { /* best effort */ }
```

## js/no-console

**console calls should not be left in production code.** Use a proper logger instead of console.* calls.

Noncompliant:

```javascript
console.log('hi');
```

Compliant:

```javascript
logger.info('hi');
```

## js/jump-in-finally

**finally blocks should not return, throw, break or continue.** A jump out of a finally block discards whatever the try or catch block was doing: its return value or its exception is silently lost.

SonarQube: S1143

Noncompliant:

```javascript
function f() { try { return g(); } finally { return 0; } }
```

Compliant:

```javascript
function f() { try { return g(); } finally { for (;;) { break; } cleanup(); } }
```

## js/no-with

**with statements should not be used.** Inside `with`, a bare name may refer to a property of the object or to a variable, depending on the object at run time. Strict mode forbids it.

SonarQube: S1321

Noncompliant:

```javascript
with (config) { f(port); }
```

Compliant:

```javascript
const c = config; f(c.port);
```

## js/duplicate-parameter

**Parameter names should be unique.** When two parameters share a name, the later one hides the earlier, whose argument becomes unreachable.

SonarQube: S1536

Noncompliant:

```javascript
function move(x, y, x) { return x + y; }
```

Compliant:

```javascript
function move(x, y, z) { return x + y + z; }
```

## js/self-assignment

**Variables should not be assigned to themselves.** `x = x` has no effect. It usually means another variable or property was meant.

SonarQube: S1656

Noncompliant:

```javascript
this.name = this.name;
```

Compliant:

```javascript
this.name = name;
items[i++] = items[i++];
```

## js/identical-operands

**Both sides of an operator should not be identical.** `a === a`, `a - a` or `a && a` always give the same result, so one side is almost always a copy-paste mistake. `x !== x` (a NaN test) and `h & h` (a 32-bit integer conversion) are idioms and allowed.

SonarQube: S1764

Noncompliant:

```javascript
if (a.length === a.length) { f(); }
```

Compliant:

```javascript
if (a.length === b.length) { f(); }
const r = next() - next();
const m = 1 << 1;
```

## js/duplicate-condition

**Conditions in an if/else-if chain or switch should be unique.** A condition repeated further down an if/else-if chain, or a repeated switch case, can never be reached: the first one always wins.

SonarQube: S1862

Noncompliant:


SonarQube: S2068

Noncompliant:

```javascript
const db = connect({ user: 'app', password: 'hunter2' });
```

Compliant:

```javascript
const db = connect({ user: 'app', password: process.env.DB_PASSWORD });
const labels = { password: 'Your password' };
const field = { password: '' };
```

## js/hardcoded-secret

**Secrets should not be hard-coded.** Tokens and API keys in the source leak with every copy of the repository. Only random-looking values are flagged: at least 16 characters, mixing letters and digits.

SonarQube: S6418

Noncompliant:

```javascript
const apiKey = 'x9Fq2LmZ7vR4tK8wB1nC6pD3';
```

Compliant:

```javascript
const apiKey = process.env.API_KEY;
const tokenHeader = 'Authorization';
```

## js/xxe

**XML parsers should not expand external entities.** With `noent: true`, libxmljs resolves external entities, so a crafted document can read local files or reach internal hosts (XXE).

SonarQube: S2755

Noncompliant:

```javascript
libxmljs.parseXml(xml, { noent: true });
```

Compliant:

```javascript
libxmljs.parseXml(xml, { noblanks: true });
```

## js/cookie-not-secure

**Cookies should have the secure flag.** Without `secure`, the cookie is also sent over plain HTTP, where anyone on the network can read it.

SonarQube: S2092

Noncompliant:

```javascript
res.cookie('sid', id, { secure: false });
```

Compliant:

```javascript
res.cookie('sid', id, { secure: true, httpOnly: true });
nodemailer.createTransport({ host, secure: false });
```

## js/cookie-not-httponly

**Cookies should have the HttpOnly flag.** Without `httpOnly`, scripts on the page can read the cookie, so any XSS can steal the session.

SonarQube: S3330

Noncompliant:

```javascript
app.use(session({ secret, cookie: { httpOnly: false } }));
```

Compliant:

```javascript
app.use(session({ secret, cookie: { httpOnly: true, secure: true } }));
```

## js/cors-any-origin

**CORS should not allow every origin.** `Access-Control-Allow-Origin: *` (also cors() with no options) lets any website read this server's responses from a visitor's browser.

SonarQube: S5122

Noncompliant:

```javascript
res.setHeader('Access-Control-Allow-Origin', '*');
```

Compliant:

```javascript
res.setHeader('Access-Control-Allow-Origin', 'https://app.example.com');
app.use(cors({ origin: ['https://app.example.com'] }));
```

## js/csp-disabled

**The Content-Security-Policy should not be disabled.** helmet's CSP limits where scripts and other content can load from; turning it off removes a key defense against XSS.

SonarQube: S5728

Noncompliant:

```javascript
app.use(helmet({ contentSecurityPolicy: false }));
```

Compliant:

```javascript
app.use(helmet({ contentSecurityPolicy: { directives: { defaultSrc: ["'self'"] } } }));
```

## js/nosniff-disabled

**MIME type sniffing should stay disabled.** Without `X-Content-Type-Options: nosniff`, browsers may run an upload or response as a script despite its declared type.

SonarQube: S5734

Noncompliant:

```javascript
app.use(helmet({ noSniff: false }));
```

Compliant:

```javascript
app.use(helmet());
```

## js/unsafe-referrer-policy

**The Referrer-Policy should not leak full URLs.** 'unsafe-url' and 'no-referrer-when-downgrade' send the full URL, including paths and query strings, to other sites.

SonarQube: S5736

Noncompliant:

```javascript
app.use(helmet.referrerPolicy({ policy: 'unsafe-url' }));
```

Compliant:

```javascript
app.use(helmet.referrerPolicy({ policy: 'no-referrer' }));
```

## js/hsts-disabled

**HTTP Strict-Transport-Security should not be disabled.** HSTS tells browsers to use HTTPS only; without it, a first plain-HTTP request can be intercepted and downgraded.

SonarQube: S5739

Noncompliant:

```javascript
app.use(helmet({ hsts: false }));
```

Compliant:

```javascript
app.use(helmet({ hsts: { maxAge: 31536000 } }));
```

## ts/no-explicit-any

**The 'any' type should not be used.** `any` disables type checking; prefer `unknown` or a precise type.

SonarQube: S4204

Noncompliant:

```typescript
let x: any = 1;
```

Compliant:

```typescript
let x: unknown = 1;
```

## js/unused-variable

**Unused local variables and functions should be removed.** A local that is never read is dead code, or a sign that something meant to use it doesn't. Names starting with `_`, and names that only leave a property out of a `...rest` destructuring, are ignored.

SonarQube: S1481

Noncompliant:

```javascript
function total(items) { const tax = 0.2; return items.length; }
```

Compliant:

```javascript
function total(items) { const tax = 0.2; return items.length * tax; }
function pick({ secret, ...rest }) { return rest; }
function f(_unused) { let _ignored = 1; }
```

## js/unused-import

**Unused imports should be removed.** An import nothing uses adds a dependency and slows loading for nothing. Uses in types and JSX count; `React` counts as used in files with JSX.

SonarQube: S1128

Noncompliant:

```javascript
import { readFile, writeFile } from 'node:fs';
readFile('a');
```

Compliant:

```javascript
import { readFile } from 'node:fs';
import React from 'react';
readFile('a');
const v = <div />;
```

## js/const-reassigned

**Constants should not be reassigned.** Assigning to a `const` throws a TypeError at run time.

SonarQube: S3500

Noncompliant:

```javascript
const count = 0;
count += 1;
```

Compliant:

```javascript
let count = 0;
count += 1;
const list = [];
list.push(1);
```

## js/redeclared

**Variables and functions should not be redeclared.** Declaring a name twice in the same scope (with `var`, `function` or as a parameter) silently replaces the first one. TypeScript's declaration merging (interfaces, namespaces, enums) is fine.

SonarQube: S2814

Noncompliant:

```javascript
function load(url) { var url = normalize(url); return fetch(url); }
```

Compliant:

```javascript
function load(url) { const normalized = normalize(url); return fetch(normalized); }
```

## js/implicit-global

**Variables should be declared before they are assigned.** Assigning to an undeclared name creates a global in sloppy mode (and throws in strict mode and modules), usually from a typo or a forgotten `let`.

SonarQube: S2703

Noncompliant:

```javascript
function count(xs) { total = 0; for (const x of xs) { total += x; } return total; }
```

Compliant:

```javascript
function count(xs) { let total = 0; for (const x of xs) { total += x; } return total; }
console.log(process.env.HOME);
```

## js/import-reassigned

**Imported names should not be reassigned.** Imports are read-only bindings: assigning to one throws in modules.

SonarQube: S6522

Noncompliant:

```javascript
import { limit } from './config';
limit = 10;
```

Compliant:

```javascript
import { limit } from './config';
let max = limit;
max = 10;
```

## js/unused-parameter

**Unused function parameters should be removed.** A parameter the function never reads is noise for callers. Only trailing ones are reported, since earlier ones hold later ones' positions, and only for functions whose arity callers can't depend on: not methods, callbacks, or functions passed by name (Express, for one, treats four-parameter middleware as error handlers).

Off by default: add `"js/unused-parameter"` to `rules.enabled` to run it.

SonarQube: S1172

Noncompliant:

```javascript
function area(width, height, unit) { return width * height; }
area(1, 2);
```

Compliant:

```javascript
function area(width, height) { return width * height; }
function onError(err, req, res, next) { res.status(500).end(); }
app.use(onError);
items.map((item, index) => index);
```

## js/shadowed-variable

**Variables should not shadow outer ones.** A declaration with the same name as one in an enclosing scope hides it, so code meaning the outer one silently gets the inner one.

Off by default: add `"js/shadowed-variable"` to `rules.enabled` to run it.

SonarQube: S1117

Noncompliant:

```javascript
function total(items) { let sum = 0; for (const item of items) { const sum = item.price; } return sum; }
```

Compliant:

```javascript
function total(items) { let sum = 0; for (const item of items) { sum += item.price; } return sum; }
```

## js/var-outside-block

**Variables should be used in the blocks where they are declared.** A `var` declared in a block is visible in the whole function, but using it outside that block relies on hoisting and is easy to misread. Declare it where it is used, or use `let`.

SonarQube: S2392

Noncompliant:

```javascript
function find(xs, y) { for (var i = 0; i < xs.length; i++) { if (xs[i] === y) break; } return i; }
```

Compliant:

```javascript
function find(xs, y) { var i; for (i = 0; i < xs.length; i++) { if (xs[i] === y) break; } return i; }
```

## js/prefer-const

**Variables that are never reassigned should be declared with const.** `const` tells readers, and the engine, that a binding never changes. Reported when every variable of a `let` declaration is initialized and never assigned again, so the fix is just the keyword.

Off by default: add `"js/prefer-const"` to `rules.enabled` to run it.

SonarQube: S3353

Noncompliant:

```javascript
let limit = 10;
export const pages = limit * 2;
```

Compliant:

```javascript
const limit = 10;
let count = 0;
count++;
let a = 1, b = 2;
b++;
export const pages = limit * 2 + count + a + b;
```

## js/collection-never-read

**Collection contents should be used.** An array, set or map that is only ever added to costs memory and work for nothing: nothing reads what it holds.

SonarQube: S4030

Noncompliant:

```javascript
function load(rows) { const seen = new Set(); for (const r of rows) { seen.add(r.id); } return rows.length; }
```

Compliant:

```javascript
function load(rows) { const seen = new Set(); for (const r of rows) { seen.add(r.id); } return seen.size; }
```

## js/unused-private-field

**Unused private class fields should be removed.** A private field (`#name`, or TypeScript `private`) can only be used inside its class; if nothing there uses it, it is dead. Decorated fields are left alone, since frameworks use them.

SonarQube: S1068

Noncompliant:

```typescript
class Cache { private hits = 0; #size = 0; get(k: string) { return k; } }
```

Compliant:

```typescript
class Cache { private hits = 0; #size = 0; constructor(private readonly store: Map<string, string>) {}
  get(k: string) { this.hits++; this.#size = this.store.size; return this.store.get(k); } }
```

## py/no-eval

**eval() and exec() should not be used.** eval()/exec() run arbitrary code and are a common injection vector.

```python
eval(user_input)
```

Compliant:

```python
ast.literal_eval(user_input)
```

## py/subprocess-shell

**Commands should not be run through a shell.** shell=True passes the command through /bin/sh, enabling command injection.

Noncompliant:

```python
subprocess.run(cmd, shell=True)
```

Compliant:

```python
subprocess.run(['ls', '-l'])
```

```python
data = pickle.loads(blob)
```

Compliant:

```python
data = json.loads(blob)
```

## py/mutable-default

**Default arguments should not be mutable.** Default values are evaluated once, so a list/dict/set default is shared between calls.

SonarQube: S5717 (related)

Noncompliant:

```python
def f(items=[]):
    return items
```

Compliant:

```python
def f(items=None):
    return items or []
```

**assert should not be called on a tuple.** `assert (cond, msg)` asserts a non-empty tuple, which is always true.

SonarQube: S5905

Noncompliant:

Compliant:

```python
assert x > 0, 'x must be positive'
```

## py/bare-except

**Bare except clauses should not be used.** `except:` also catches SystemExit and KeyboardInterrupt. Catch a specific exception.

SonarQube: S5754 (related)

Noncompliant:

```python
try:
    f()
except:
    pass
```

Compliant:

```python
try:
    f()
except ValueError:
    pass
```

## py/none-comparison

**None should be compared with 'is'.** `== None` can be overridden by __eq__; use `is None` / `is not None`.

Noncompliant:

```python
if x == None:
    pass
```

Compliant:

```python
if x is None:
    pass
```

## c/no-gets

**gets() should never be used.** gets() cannot limit input size and always allows a buffer overflow.

Noncompliant:

```c
void f(char *b) { gets(b); }
```

Compliant:

```c
void f(char *b, int n) { fgets(b, n, stdin); }
```

## c/unsafe-string-function

**Unbounded string functions should not be used.** strcpy, strcat, sprintf and vsprintf do not check the destination size.

Noncompliant:

```c
void f(char *d, const char *s) { strcpy(d, s); }
```

Compliant:

```c
void f(char *d, const char *s, int n) { snprintf(d, n, "%s", s); }
```

## c/assignment-in-condition

**Assignments should not be used as conditions.** `if (x = y)` is almost always a typo for `==`. Use double parentheses if intended.

Noncompliant:

```c
void f(int x) { if (x = 5) { g(); } }
```

Compliant:

```c
void f(int x) { if (x == 5) { g(); } if ((x = h())) { g(); } }
```

## c/goto

**goto should not be used.** goto makes control flow hard to follow.

Noncompliant:

```c
void f(void) { goto end; end: return; }
```

Compliant:

```c
void f(void) { return; }
```
