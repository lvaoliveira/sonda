# ADR-0033: Ruby support

- Status: **accepted** for the language; the rules are a first batch
- Date: 2026-11-26

## Context

Ruby is the third language from the roadmap's list (Go, PHP, Ruby, Kotlin),
after PHP ([ADR-0032](0032-php.md)). Most Ruby in production is Rails, so
what a first batch of rules can say about security is mostly about what Rails
makes easy: a query built in a string, `params` reaching `send` or
`File.read`, `html_safe`, `permit!`.

As with Go and PHP, there is no SonarQube Ruby rule list to measure against
yet, so these rules carry no SonarQube key and the parity table has no Ruby
row. They follow RuboCop and Brakeman.

## Decision

### Grammar

[tree-sitter-ruby](https://github.com/tree-sitter/tree-sitter-ruby) 0.23.1,
MIT licensed and maintained by the tree-sitter organization, generated C with
an external scanner, so it joins the C surface worker isolation
([ADR-0003](0003-isolate-parsing.md), [ADR-0004](0004-sandbox-workers.md))
contains and the fuzzer exercises; a Ruby seed (`11`) joins the corpus. It is
from 2024, well past the 14-day release age CI checks for
([ADR-0009](0009-dependencies-and-advisories.md)).

### The language

- `Lang::Ruby`, id `ruby`, for `.rb`, `.rake`, `.gemspec` and `.ru`, last in
  `lang::ALL`. Not `Rakefile` or `Gemfile`, which have no suffix to tell them
  by.
- Metrics: `def` and `def self.x` are functions; a block, a `do` block and a
  lambda are part of the method around them, one level deeper, as closures
  are in the other languages. `if`, `unless` and `elsif` are ifs, and so are
  their modifier forms (`x if y`) with the loops (`for`, `while`, `until`,
  `x while y`), `rescue` (and `x rescue y`) and `a ? b : c`: one branch each.
  `case` is a switch, each `when` (or `in`, for pattern matching) adding one
  and an `else` nothing. `&&`, `||`, `and` and `or` count as everywhere.
  Checked by hand on a method with an `if`, an `&&`, an `elsif`, an `else`, a
  `do` block holding `puts x unless x.zero?`, a `case` of two `when`s and a
  `rescue`: cyclomatic 9 and cognitive 9 (the `unless` costs 3: 1, and 2 for
  being inside an `else` and a block).
- Highlighting: keywords, `#` comments and backticks. `=begin ... =end`
  isn't marked, since it starts a line.
- The semantic layer ([ADR-0008](0008-semantic-layer.md)) has a Ruby binder
  (`semantic/ruby.rs`), which reads the model the way Ruby scopes locals:
  `x` is a method call until `x = ..` has been seen (the grammar has one
  node for both), so the first assignment declares it and an identifier is a
  use only if a declaration is visible; a method (`def`, `def self.m`) and a
  class body see nothing outside them; a block, a `do` block and a lambda see
  the locals around them and hide those they share a name with by their
  parameters. What binds: the targets of an assignment (`a = ..`, `a[i] = ..`,
  `a, (b, *c) = ..`, `a ||= ..`), a `for`'s variable, a `rescue`'s variable,
  and parameters. A called method's name is never a use.

### The rules

Thirty-two rules that the file's own text proves, with no types and no flow,
each with an example the test suite runs both ways:

- Bugs: `ruby/self-assignment`, `ruby/identical-operands`,
  `ruby/same-condition-in-chain`, `ruby/duplicate-when`,
  `ruby/unreachable-code`, `ruby/rescue-exception` (`rescue Exception` also
  catches `SystemExit` and `Interrupt`) and `ruby/duplicate-hash-key`
  (`a:`, `:a` and `"a":` are the same key).
- Smells: `ruby/empty-rescue`, `ruby/nil-comparison`, `ruby/debugger-call`
  (`binding.pry`, `byebug`), `ruby/collapsible-if`, `ruby/redundant-return`,
  `ruby/method-name-camelcase`, `ruby/class-variable`,
  `ruby/global-variable`, and `ruby/empty-method`, **off by default**.
- Vulnerabilities, with CWE and OWASP: `ruby/eval`, `ruby/command-execution`,
  `ruby/sql-interpolation`, `ruby/unsafe-deserialization`, `ruby/weak-hash`,
  `ruby/weak-cipher`, `ruby/weak-random`, `ruby/tls-unverified`,
  `ruby/hardcoded-credentials`, `ruby/permissive-file-mode`,
  `ruby/reflection-from-params`, `ruby/path-from-params`,
  `ruby/mass-assignment`, `ruby/html-safe`, `ruby/redirect-from-params` and
  `ruby/csrf-disabled`. The ones about `params` look for the name itself;
  following a value to it waits for taint analysis.

Precision comes before recall, and real code set it. On RailsGoat (a
deliberately vulnerable Rails app), Sinatra, Rack, Sidekiq and Rails (about
700,000 lines), the first version reported 1,396 findings and this one 627:

- `ruby/empty-method` gave 557 findings in Rails alone: a controller action
  that only renders its view, a hook a subclass overrides and a null object
  are idioms, so the rule is off unless enabled.
- A rule for `x == true` and `x == false` is gone: in Ruby they're not
  `x` and `!x` (a value can be `nil`), and they gave 152 findings.
- `ruby/unreachable-code` reported the heredoc after `raise <<~MSG`, which
  the grammar makes a statement of its own after the `raise`.
- `ruby/identical-operands` reported `0.0 / 0.0`, how a test makes NaN.
- `ruby/unsafe-deserialization` leaves alone `Marshal.load(Marshal.dump(x))`,
  a deep copy, and `YAML.load(File.read(path))`, the program's own file.
- `ruby/eval` leaves alone a `class_eval` of a string with `#{}` in it, which
  is how a library defines its methods; `eval` itself is always reported.

Rails reports what it does on purpose (`Marshal.load` of its own cache,
`eval` in its tests), which is what these rules are for: someone decides
each one. RailsGoat's report finds what its authors put there: SQL built in
a string, MD5 for passwords, `permit!`, `constantize` on `params`, a
hard-coded secret token.

### Taint analysis

Seven more rules, `ruby/sql-injection`, `ruby/command-injection`,
`ruby/path-injection`, `ruby/open-redirect`, `ruby/ssrf`,
`ruby/code-injection` and `ruby/xss`, follow a value from `params`,
`cookies` or `request` (its `params`, `body`, `url`, `headers`, `env`, ...)
through assignments, interpolation, concatenation, the methods that join
text, a block over a collection (`params[:ids].each { |id| .. }`), `<<` and
`push`, and the methods of the file, into the queries, commands, paths,
redirects, outgoing requests, `eval`/`send`/`constantize` calls and
`raw`/`html_safe` they reach, with the path it took (ADR-0027). The engine
is the shared one; what Ruby adds:

- A method returns its last expression as well as what `return` says, so a
  summary reads both (`Body` gets an optional "implicit value").
- `@name` is a variable of its class, so `before_action`'s `@q = params[:q]`
  reaches the action's `where("n = #{@q}")`.
- A number (`to_i`, `Integer()`), a boolean (`include?`, `blank?`), what a
  sanitizer for the sink makes (`Shellwords.escape`, `File.basename`, `h`,
  `sanitize_sql`) isn't a request's value; a value tested
  (`ALLOWED.include?(x)`, `x =~ /\A\d+\z/`, a `case` of literals, a method
  called `valid_..`/`allowed?`) is validated, and so is an expression that was
  tested as written (`include?(params[:t])`, then `params[:t]`).
- Only the start of an address decides a redirect or a request, so
  `"/orders/#{id}"` is safe, `"#{base}/x/#{id}"` is decided by `base`, and
  `url += "?#{query}"` changes nothing; `request.path` and `request.host`
  can't change where a redirect goes; `only_path: true` and `allow_other_host:`
  say the program decided.
- A hash handed whole to `where` or `find_by` binds its values, and
  `execute`, `query` and `exists?` are queries only on a connection
  (`conn.execute`), not on `Search.execute` or `I18n.exists?`; `obj.attr = v`
  doesn't make `obj` text.

Running them on RailsGoat finds what the app plants: `constantize` and
`const_get` on `params[:class]`, an open redirect, a path from `params`, SQL
interpolation and `raw(params[..])`. On Sinatra, Rack, Sidekiq, Rails,
Mastodon, Discourse and Redmine (about 1.5 million lines) the first version
gave 30 findings in the three applications and this one 11, and none in the
four frameworks except one in Sidekiq: a redirect built from the `Referer`
header, which is a hotspot. These were the noise: a hash or `params.permit`
passed whole to `where` (bound), `Search.execute(params[:term])` and
`I18n.exists?(params[:id])` (not SQL), `redirect_to request.path`,
`url += "?#{request.query_string}"`, a string that starts with a value the
program set and then adds `params[:x]` (the engine let the later part
decide), an `html_safe` the name heuristic took for a check of its own
receiver, and `@project` made text by `@project.safe_attributes = params`.

**Known limits.** The model is flow-insensitive: a variable that was ever
written a request's value is tainted wherever it's read, and the idioms above
are how it's told otherwise (PHP's reassignment versions, [ADR-0032](0032-php.md),
aren't built for Ruby yet). A heredoc isn't followed (`find_by_sql(<<~SQL)`).
A call to a method of another file isn't followed, nor one the class
inherits; `params` through a helper another file defines is.

## Consequences

- Ruby files are scanned, measured and checked, and show in reports, SARIF
  and the web app. A scan of Rails (3,580 files, 614,000 lines) takes 1.8 s.
- The rule list is a first batch, not measured against SonarQube.
- Ruby's taint analysis stays within a file: the project pass doesn't read
  Ruby calls, so a `params` value passed to a method of another file reaches
  its sinks only through the rules about a call's shape.
- The shared credential-value check (a placeholder, a mask, the name of
  another setting) moves to the catalog, used by PHP and Ruby.
- Seven taint rules (below) follow a request's value within a file.

## Alternatives

- **Waiting for a SonarQube Ruby list**: as for Go and PHP, that shouldn't
  hold the language back.
