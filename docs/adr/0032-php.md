# ADR-0032: PHP support

- Status: **accepted** for the language; the rules are a first batch
- Date: 2026-11-26

## Context

PHP is the second language from the roadmap's list (Go, PHP, Ruby, Kotlin),
after Go ([ADR-0031](0031-go.md)). It is the most injection-prone of the
four, so what a first batch of rules can say about security is worth the
most here: SQL built from strings, commands, `include` of a client's value,
`unserialize`, `eval`.

As with Go, there is no SonarQube PHP rule list to measure against yet, so
these rules carry no SonarQube key and the parity table has no PHP row.

## Decision

### Grammar

[tree-sitter-php](https://github.com/tree-sitter/tree-sitter-php) 0.25.1, MIT
licensed and maintained by the tree-sitter organization, generated C with an
external scanner, so it joins the C surface worker isolation
([ADR-0003](0003-isolate-parsing.md), [ADR-0004](0004-sandbox-workers.md))
contains and the fuzzer exercises; a PHP seed (`10`) joins the corpus. It is
pinned to `=0.25.1`: 0.25.2 was a week old, under the 14-day release age
CI checks for ([ADR-0009](0009-dependencies-and-advisories.md)).

It's the grammar for PHP in HTML (`LANGUAGE_PHP`), not `php_only`: a `.php`
file is usually a template with `<?php ... ?>` in it, and the text between is
a node of its own, so only the code is parsed as PHP.

### The language

- `Lang::Php`, id `php`, for `.php`, `.phtml` and the old version suffixes
  (`.php5`, `.php7`, ...), last in `lang::ALL`. Not `.inc`, which is as often
  something else.
- Metrics: functions, methods, anonymous functions and arrow functions are
  functions; `for`, `foreach`, `while`, `do`, `catch` and `?:` are branches;
  `switch` and `match` are switches, each `case` and match arm adding one and
  a `default` nothing. `elseif` and `else if` cost one without nesting, as
  `else if` does elsewhere. Checked by hand on a function with a `foreach`,
  two nested `if`s, a `for`, a `switch` of two cases, an `elseif` and an
  `else`: cyclomatic 8 and cognitive 17.
- Highlighting: keywords and scalar types, `//` and `#` comments, backticks
  (the shell operator).
- The semantic layer ([ADR-0008](0008-semantic-layer.md)) has a PHP binder
  (`semantic/php.rs`), which reads the model the way PHP scopes variables:
  they're the function's, whatever block they're in, and the first binding
  declares them; a function sees nothing outside it (not the file's
  variables, which take a `global $x`, and not the function around it); an
  anonymous function imports what its `use ($a, &$b)` lists; an arrow function
  (`fn($x) => $x + $y`) takes the whole scope around it by value. `$this` and
  the superglobals are no variables here, and the taint engine reads them by
  name. What binds: the targets of an assignment (`$a = ..`, `$a[] = ..`,
  `[$a, $b] = ..`), a `foreach`'s key and value, a `catch`'s variable,
  `global`, `static`, a closure's `use` and parameters.

### The rules

Twenty-eight rules that the file's own text proves, with no types and no
flow, each with an example the test suite runs both ways:

- Bugs: `php/self-assignment`, `php/identical-operands`,
  `php/same-condition-in-chain`, `php/duplicate-case`, `php/unreachable-code`,
  `php/hash-loose-comparison` (`md5($x) == $h`, which "magic hashes" such as
  `0e123` defeat), `php/empty-catch`, `php/removed-mysql-api` (the `mysql_`
  functions, removed in PHP 7).
- Smells: `php/error-suppression` (`@`), `php/collapsible-if`,
  `php/redundant-bool-literal`, `php/empty-function`, `php/debug-output`
  (`var_dump`, `print_r`), and `php/method-name-underscore`, **off by
  default**.
- Vulnerabilities, with CWE and OWASP: `php/eval`,
  `php/include-from-request`, `php/command-execution`,
  `php/sql-concatenation`, `php/unserialize`, `php/weak-hash`,
  `php/weak-cipher`, `php/weak-random`, `php/tls-unverified`,
  `php/hardcoded-credentials`, `php/permissive-file-mode`,
  `php/extract-request`, `php/phpinfo`, `php/xxe`.

Precision comes before recall, and running the rules on real code is what
set it. On DVWA (a deliberately vulnerable app), Slim, monolog, CodeIgniter 3
and WordPress (about 600,000 lines), the first version reported 9,380
findings and this one 1,325. These were the noise:

- `php/method-name-underscore` gave 4,646 findings in WordPress and 1,004 in
  CodeIgniter, which name methods in snake_case on purpose. PSR-1's camelCase
  isn't every project's convention, so the rule is off unless enabled.
- `php/redundant-bool-literal` reported `$x === true`, which isn't the same as
  `$x` (it's false for `1` and `'a'`): 1,295 findings in WordPress. Only a loose
  comparison (`==`, `!=`) with a boolean is redundant: 8 now.
- `php/sql-concatenation` reported `"... FROM $wpdb->posts ..."` and
  `{$this->table}`: a property is the program's own value (a table name),
  while a variable or an element (`$_GET['id']`) can be a client's. It also
  leaves alone a value made safe for where it goes (`intval`,
  `mysqli_real_escape_string`, `escapeshellarg`) and a cast to a number.
  333 findings in WordPress became 92, which are variables interpolated into
  queries, the pattern the rule exists for.
- `php/hardcoded-credentials` reported placeholders (`'password_here'`,
  `'*****'`) and values that name another setting (`'password' => 'FTP_PASS'`):
  a value with no digit that says `pass`, `pwd`, `key`, `secret` or `token` is a
  reference, not a secret.

A function is matched by its name without regard to case or namespace
(`\MD5($x)` is `md5`), as PHP reads it.

DVWA's SQL injections aren't found by these rules: it builds the query in a
variable (`$query = "... '$id'"; mysqli_query($db, $query)`), and they see
only a string written in the call. Taint analysis, below, finds them.

### Taint analysis

Seven more rules (`php/sql-injection`, `php/command-injection`,
`php/path-injection`, `php/open-redirect`, `php/ssrf`, `php/code-injection`
and `php/xss`) follow a client's value to the sink ([ADR-0027](0027-taint-analysis.md)),
with the path it took. `xss` needed a sink kind the other engines didn't have
(`SinkKind::Html`, which they ignore): for PHP, the page that echoes
`$_GET['name']` is the headline vulnerability.

- **Sources:** `$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, `$_FILES` (but not
  where the server put the upload: `['tmp_name']`, `['size']`, `['error']`),
  the `$_SERVER` keys a client chooses (`HTTP_*`, `REQUEST_URI`,
  `QUERY_STRING`, `PHP_SELF`, `PATH_INFO`), `php://input`, the headers and
  `filter_input`, and a request object a function takes (Laravel's and
  Symfony's `Request`, PSR-7's `ServerRequestInterface`: `$request->input('q')`,
  `$request->query->get('q')`, `getQueryParams()`, and Laravel's
  `$request->email`).
- **Sinks:** the query functions and methods (not a prepared statement's
  `execute`, whose arguments are bound), the commands, the files and
  `include`/`require`, `header('Location: ...')` and `wp_redirect`, outgoing
  requests (`curl_setopt`, `file_get_contents`, Guzzle), `eval`, and what a
  page prints (`echo`, `print`, `<?= ?>`).
- **Through** concatenation and interpolation, the functions that change text
  (`sprintf`, `trim`, `substr`, `str_replace`, `explode`, `implode`, ...),
  array elements and properties, `foreach`, destructuring, `preg_match`'s
  matches, the functions and methods of the file (by name; for a method by its
  class: `$this`, `self::`, a variable declared with the class or made by
  `new`), and across files: PHP has no packages, so a call is to the function
  of that name, or the method of that class, in any other PHP file.
- **Cleared by** `htmlspecialchars`, `intval`, `escapeshellarg`, `basename`,
  the `esc_*` and the other functions a call to an unknown function turns into
  (it returns an untainted value); a numeric cast; a test (`is_numeric`,
  `in_array`, `preg_match`, `ctype_*`, `filter_var`, a function called
  `validate...`) or a comparison with a literal, looking through
  `$octet[0]` and `strtolower($ext)`; and a variable the program passes
  through a sanitizer or a numeric cast back into itself (`$id =
  mysqli_real_escape_string($db, $id)`, `$id = (int) $id`).
- **Only the start of an address** sets where a redirect goes: after
  `/orders/` a value can't change the host, after `https://` the next part is
  the host. The `Host` the client wrote isn't a source for a redirect, and
  `wp_safe_redirect` checks the host itself.

Real code decided most of that. On DVWA the first scan gave 59 findings;
three fixes (checks through a subscript or a text function, the server's
upload keys, a variable passed back through a sanitizer) took 20 of them away,
among them its upload "impossible" level, which is built to be safe, and it
gives 39: SQL injection in `sqli`, `sqli_blind`, `brute`,
`captcha`, `csrf`, `bac` and `xss_s`, command injection in `exec`, file
inclusion in `view_source`, the `callback` of the JSONP endpoint, and a
`$_COOKIE` theme echoed into every page. WordPress went from 28 to 16
(`wp_safe_redirect`, the `Host` header, and ids cast to `int` first). Slim,
monolog and CodeIgniter 3 give none.

**Flow.** The model keeps one taint per variable, so a variable that was ever
written a client's value was tainted wherever it was read. A plain `$x = v;`
that is a statement of a block and not in a loop now kills what `$x` held
before, for the reads after it in that block: those reads get a version of
the variable of their own. The writes of a version are also the writes of
the variable it replaced, so a read after the block (a reassignment in an
`if`) still sees both. A reassignment in a loop kills nothing, since the
read at the top of the loop sees the last pass's write; and a check, or a
variable passed back through a sanitizer, validates every version of it, as
before. DVWA's `exec/source/impossible.php`, whose `$target` is set from the
request and then from octets that were checked, no longer reports. The
versions are made only in files that name a source (`$_GET`, a `Request`…):
the other files' functions are only reached through parameters, and the
walk costs about a tenth of the scan.

**Properties.** `$this->name` is a variable of the class it's in. A method
that sets it from a request's value taints the reads of it in the class's
other methods; a check on it validates it; a property declared (or promoted
by a constructor) with a request type holds a request object. A value
passed *into* a method and stored (`new Foo($_GET['x'])`, then
`$this->x = $x`) isn't followed: a summary has no effect on a property yet.

**Inheritance.** A call to a method the class doesn't define goes to the
nearest ancestor that does, through `extends`, a trait's `use` and
`parent::`, in the file and across files (each file lists its classes'
parents and methods for the project pass); an override is the method
called. A call through an interface or on a variable of an unknown class
isn't resolved.

## Consequences

- PHP files are scanned, measured and checked, and show in reports, SARIF and
  the web app. A scan of WordPress (528,000 lines of PHP) takes 2.4 s.
- The rule list is a first batch, not measured against SonarQube.
- PHP has a binder and taint analysis, within a file and across the
  project's. A WordPress scan (528,000 lines of PHP) takes about 6 s, up from
  2.4 s with the rules alone.

## Alternatives

- **`php_only`**: it would treat the HTML of a template as a syntax error.
- **Waiting for a SonarQube PHP list**: as for Go, that shouldn't hold the
  language back.
