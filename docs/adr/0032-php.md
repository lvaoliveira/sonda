# ADR-0032: PHP support

- Status: **accepted** for the language; the rules are a first batch
- Date: 2026-11-26

## Context

PHP is the second language from the roadmap's list (Go, PHP, Ruby, Kotlin),
after Go ([ADR-0031](0031-go.md)). It is the most injection-prone of the
four, so what a first batch of rules can say about security is worth the
most here: SQL built from strings, commands, `include` of a client's value,
`unserialize`, `eval`.

As with Go, there is no SonarQube PHP rule list to measure against yet, so
these rules carry no SonarQube key and the parity table has no PHP row.

## Decision

### Grammar

[tree-sitter-php](https://github.com/tree-sitter/tree-sitter-php) 0.25.1, MIT
licensed and maintained by the tree-sitter organization, generated C with an
external scanner, so it joins the C surface worker isolation
([ADR-0003](0003-isolate-parsing.md), [ADR-0004](0004-sandbox-workers.md))
contains and the fuzzer exercises; a PHP seed (`10`) joins the corpus. It is
pinned to `=0.25.1`: 0.25.2 was a week old, under the 14-day release age
CI checks for ([ADR-0009](0009-dependencies-and-advisories.md)).

It's the grammar for PHP in HTML (`LANGUAGE_PHP`), not `php_only`: a `.php`
file is usually a template with `<?php ... ?>` in it, and the text between is
a node of its own, so only the code is parsed as PHP.

### The language

- `Lang::Php`, id `php`, for `.php`, `.phtml` and the old version suffixes
  (`.php5`, `.php7`, ...), last in `lang::ALL`. Not `.inc`, which is as often
  something else.
- Metrics: functions, methods, anonymous functions and arrow functions are
  functions; `for`, `foreach`, `while`, `do`, `catch` and `?:` are branches;
  `switch` and `match` are switches, each `case` and match arm adding one and
  a `default` nothing. `elseif` and `else if` cost one without nesting, as
  `else if` does elsewhere. Checked by hand on a function with a `foreach`,
  two nested `if`s, a `for`, a `switch` of two cases, an `elseif` and an
  `else`: cyclomatic 8 and cognitive 17.
- Highlighting: keywords and scalar types, `//` and `#` comments, backticks
  (the shell operator).
- The semantic layer ([ADR-0008](0008-semantic-layer.md)) has no PHP binder
  yet, so the rules about names, and taint analysis, wait for one.

### The rules

Twenty-eight rules that the file's own text proves, with no types and no
flow, each with an example the test suite runs both ways:

- Bugs: `php/self-assignment`, `php/identical-operands`,
  `php/same-condition-in-chain`, `php/duplicate-case`, `php/unreachable-code`,
  `php/hash-loose-comparison` (`md5($x) == $h`, which "magic hashes" such as
  `0e123` defeat), `php/empty-catch`, `php/removed-mysql-api` (the `mysql_`
  functions, removed in PHP 7).
- Smells: `php/error-suppression` (`@`), `php/collapsible-if`,
  `php/redundant-bool-literal`, `php/empty-function`, `php/debug-output`
  (`var_dump`, `print_r`), and `php/method-name-underscore`, **off by
  default**.
- Vulnerabilities, with CWE and OWASP: `php/eval`,
  `php/include-from-request`, `php/command-execution`,
  `php/sql-concatenation`, `php/unserialize`, `php/weak-hash`,
  `php/weak-cipher`, `php/weak-random`, `php/tls-unverified`,
  `php/hardcoded-credentials`, `php/permissive-file-mode`,
  `php/extract-request`, `php/phpinfo`, `php/xxe`.

Precision comes before recall, and running the rules on real code is what
set it. On DVWA (a deliberately vulnerable app), Slim, monolog, CodeIgniter 3
and WordPress (about 600,000 lines), the first version reported 9,380
findings and this one 1,325. These were the noise:

- `php/method-name-underscore` gave 4,646 findings in WordPress and 1,004 in
  CodeIgniter, which name methods in snake_case on purpose. PSR-1's camelCase
  isn't every project's convention, so the rule is off unless enabled.
- `php/redundant-bool-literal` reported `$x === true`, which isn't the same as
  `$x` (it's false for `1` and `'a'`): 1,295 findings in WordPress. Only a loose
  comparison (`==`, `!=`) with a boolean is redundant: 8 now.
- `php/sql-concatenation` reported `"... FROM $wpdb->posts ..."` and
  `{$this->table}`: a property is the program's own value (a table name),
  while a variable or an element (`$_GET['id']`) can be a client's. It also
  leaves alone a value made safe for where it goes (`intval`,
  `mysqli_real_escape_string`, `escapeshellarg`) and a cast to a number.
  333 findings in WordPress became 92, which are variables interpolated into
  queries, the pattern the rule exists for.
- `php/hardcoded-credentials` reported placeholders (`'password_here'`,
  `'*****'`) and values that name another setting (`'password' => 'FTP_PASS'`):
  a value with no digit that says `pass`, `pwd`, `key`, `secret` or `token` is a
  reference, not a secret.

A function is matched by its name without regard to case or namespace
(`\MD5($x)` is `md5`), as PHP reads it.

DVWA's SQL injections aren't found: it builds the query in a variable
(`$query = "... '$id'"; mysqli_query($db, $query)`), and these rules see only
a string written in the call. That's taint analysis's job, and the next piece.

## Consequences

- PHP files are scanned, measured and checked, and show in reports, SARIF and
  the web app. A scan of WordPress (528,000 lines of PHP) takes 2.4 s.
- The rule list is a first batch, not measured against SonarQube.
- The next steps are a PHP binder, then taint analysis from `$_GET`,
  `$_POST`, `$_REQUEST` and `$_COOKIE` into `mysqli_query`, `exec`, `include`
  and the like, then across files.

## Alternatives

- **`php_only`**: it would treat the HTML of a template as a syntax error.
- **Waiting for a SonarQube PHP list**: as for Go, that shouldn't hold the
  language back.
